Reference

Glossary

Every key term in the guide in one sentence, with a link to the chapter section that explains it properly.

A B C D E F G H I J L M N O P R S T V W

A

A2A (Agent2Agent)
An open protocol, announced by Google in 2025 and later moved to the Linux Foundation, that lets one agent find another through its published “agent card” and send it tasks over HTTP, without seeing that agent's tools or memory. See Ch 17 · Standard protocols: MCP and A2A
Agent
An LLM running in a loop in which the model itself picks the next step (usually a tool call) after seeing the result of the last one, until it decides the task is done or the harness stops it. See Ch 02 · Agents: the model owns the loop
Agent-computer interface (ACI)
The tools as the model experiences them (names, descriptions, parameters, output size and error messages), designed with the same care you would give a human user interface. The term comes from the SWE-agent paper (Yang et al., 2024). See Ch 04 · Tool design is interface design
Agent loop
The core cycle of every agent: call the model, run any tools it asked for, add the results to the history, and repeat until a stop condition fires. See Ch 03 · The loop in code
Aggregation
The step where a parent agent combines its children's results into one answer, including deciding what to do with results that are missing, failed or contradictory. See Ch 16 · Aggregation
Augmented LLM
An LLM given retrieval, tools and memory, which Anthropic's “Building effective agents” treats as the basic building block of every workflow and agent. See Ch 02 · The augmented LLM
Autonomy spectrum
The idea that being “agentic” is a matter of degree: systems range from fixed code that calls a model once to agents that own the whole control flow, and cost and unpredictability rise as the model decides more. See Ch 02 · The autonomy spectrum

B

Backoff (exponential, with jitter)
A retry policy that waits longer after each failure, typically doubling the delay each time (exponential), and adds a random amount (jitter) so that many clients that failed together don't all retry at the same moment. See Ch 11 · Retries, backoff and jitter
Blackboard
A shared store that agents read from and write to, so they coordinate through what is posted there instead of messaging each other directly. See Ch 15 · Shared medium: the blackboard
Budget (token, step, time, agent)
A hard limit, enforced in code rather than asked for in the prompt, on what a run may use up: tokens, steps (model calls), wall-clock time, or the number of agents it creates. See Ch 11 · Budgets and where they are enforced
Budget pool vs slice
Two ways to share a run's budget among child agents: slices give each child a fixed share up front (simple, but unused share is wasted), while a pool lets every agent draw from one shared balance (efficient, but one greedy child can starve the rest). See Ch 16 · Budgets: slices or a pool

C

CaMeL
A prompt-injection defense from Google DeepMind (Debenedetti et al., 2025) that makes the dual-LLM pattern rigorous: a privileged model writes the plan as a small program in restricted Python, and a custom interpreter runs it, tracking where every value came from and checking a security policy before each tool call. See Ch 12 · Dual LLM and CaMeL
Chain-of-thought (CoT)
Getting a model to write out intermediate reasoning steps before its final answer, which tends to improve accuracy on multi-step problems. See Ch 05 · Chain-of-thought and self-consistency
Checkpoint
A saved snapshot of a run's state, usually taken after each step, so the run can resume after a crash, or be replayed or forked from that point. See Ch 09 · Checkpoints, resume, replay and fork
Circuit breaker
A guard on calls to one dependency that stops sending them, failing fast instead, once recent failures cross a threshold, and later lets a trial call through to test whether the dependency has recovered. See Ch 11 · Circuit breakers
CoALA
“Cognitive Architectures for Language Agents” (Sumers et al., 2024), a framework that describes an agent by its memory modules (working, episodic, semantic, procedural), its actions and its decision cycle. See Ch 07 · Memory systems
Compaction
Summarizing or trimming the conversation history as it nears the context limit, so the agent can keep working from a shorter context that keeps what matters. See Ch 06 · Compaction and clearing old tool results
Consolidation
Periodically merging, deduplicating and summarizing stored memories (for example, turning many similar episodes into one general fact) so the memory store stays small and consistent. See Ch 07 · Memory systems
Context engineering
Deciding exactly which tokens go into the model's context window at each step (instructions, tools, history, retrieved data) so the model gets the smallest set of high-signal information it needs. See Ch 06 · The big idea
Context rot
The observed tendency of a model to use the information in its context less reliably as the input grows longer, even on simple tasks. See Ch 06 · Why more context isn't free
Context window
The maximum amount of text, counted in tokens, that a model can work with in one call; because the model keeps nothing between calls, it is the model's only memory. See Ch 01 · Stateless: the context window is its only memory
Contract net
A task-allocation protocol (Reid G. Smith, 1980) in which a manager announces a task, capable agents send bids, the manager awards the task to the best bid, and the winner reports the result. See Ch 17 · The contract net protocol
Coroutine
In Python, a function defined with async def that can pause at each await and let other coroutines run on the same thread while it waits for I/O. See Ch 10 · Concurrency for agents

D

Deadlock
A state in which two or more agents or tasks are each waiting for another to act first, so none of them can ever continue; a timeout on every wait is the usual way out. See Ch 17 · Coordination failures
Debate (multi-agent)
A pattern in which several agents answer the same question, read each other's answers and revise over a few rounds, in the hope of a better final answer than any one would give alone (the evidence on when it helps is mixed). See Ch 15 · Collective: debate and voting
Dual-LLM pattern
A prompt-injection defense proposed by Simon Willison in 2023, in which the privileged LLM that chooses actions never sees untrusted content, and a quarantined LLM that reads untrusted content has no tools. See Ch 12 · Dual LLM and CaMeL
Durable execution
Running a workflow so that every completed step is recorded, and after a crash the run resumes from that history without redoing finished steps; Temporal is the best-known runtime of this kind. See Ch 09 · Durable execution and idempotency

E

Embedding
A list of numbers (a vector) that a model produces to represent the meaning of a piece of text, so texts with similar meanings land close together and can be found by similarity search. See Ch 07 · Memory systems
Emergence
A property of a group that no individual has and no rule mentions, such as an ant colony settling on a short path that no single ant's rule describes. See Ch 18 · What “swarm intelligence” actually means
Episodic memory
Memory of specific past events, such as earlier runs, conversations or attempts, that an agent can recall to guide what it does now. See Ch 07 · Memory systems
Evaluator-optimizer
A workflow pattern in which one LLM call produces an answer and another evaluates it and gives feedback, looping until the evaluation passes or a limit is reached. See Ch 02 · Five workflow patterns
Event loop
The scheduler at the heart of Python's asyncio, which runs many coroutines on one thread and switches to another one whenever the current one awaits something that isn't ready yet. See Ch 10 · Concurrency for agents
Event sourcing
Storing a run as an append-only log of the events that happened, not just its current state, so the state can be rebuilt, and the history audited, by replaying the log. See Ch 09 · Event sourcing

F

Fan-out
The number of children one agent may spawn; together with the depth limit it bounds how big a spawn tree can grow, up to 1 + f + f² + … + fd agents. See Ch 16 · Limits and the growth math
Function calling
Another name, used by OpenAI and others, for tool use: the model returns a structured request to call a named function with JSON arguments, and your code runs it. See Ch 04 · The protocol

G

Graceful degradation
Carrying on with reduced but clearly labelled output when part of the system fails, for example returning four of five sub-results and saying which one is missing, rather than failing the whole task. See Ch 11 · Graceful degradation and partial results
Guardrail
A check that runs around the agent rather than inside its reasoning: on its input, on each tool call before it executes, or on its output before that output leaves the agent. See Ch 11 · Validating output, and guardrails

H

Handoff
Passing control of a conversation from one agent to another, usually by having the first agent call a transfer tool, so the new agent takes over rather than reporting back. See Ch 15 · Decentralized: mesh and handoff
Harness
All the code around the model that turns it into an agent: the loop driver, model client, tool executor, context manager, state store, permissions, budgets, tracing and human-approval hooks. See Ch 08 · Harness, framework, scaffold, SDK
Hierarchical topology
A multi-agent structure in which managers delegate to sub-managers, who delegate to workers, forming a tree; in effect, orchestrator-worker applied at more than one level. See Ch 15 · Centralized: orchestrator-worker and hierarchy
Human-in-the-loop (HITL)
Designing a run to pause at chosen points so a person can approve, edit or reject what the agent proposes before it continues. See Ch 09 · Human-in-the-loop interrupts

I

Idempotency
The property that doing an operation twice has the same effect as doing it once, which is what makes it safe to retry after a crash or a timeout. See Ch 11 · Idempotency
Indirect prompt injection
An attack in which instructions are hidden in content the agent reads while working (a web page, an email, a document, a tool result) rather than typed by the user, and the model follows them as if they were legitimate. See Ch 12 · Prompt injection: direct and indirect
is_error
A flag on a tool_result block telling the model that the tool call failed, so the error message comes back as an observation the model can read and react to instead of crashing the loop. See Ch 04 · Errors are observations

J

Just-in-time retrieval
Giving the agent tools to fetch information at the moment it needs it (search a folder, read a file by path) instead of loading everything into the context up front. See Ch 06 · Just-in-time retrieval vs preloading

L

Least privilege
Giving each agent and tool only the permissions its task needs, so that a confused or hijacked agent can do as little damage as possible. See Ch 12 · Least privilege and capability scoping
Lethal trifecta
Simon Willison's 2025 name for an agent that combines access to private data, exposure to untrusted content and a way to send data out, which together let injected instructions steal that data. See Ch 12 · The lethal trifecta
Livelock
A coordination failure in which agents stay busy (for example, politely deferring to each other over and over) but none of them makes progress. See Ch 17 · Coordination failures
LLM-as-judge
Using a language model to grade outputs against a rubric; it scales to open-ended answers but has known biases (such as favoring one position, longer answers or its own outputs) and must be checked against human labels. See Ch 13 · Graders: code, model, human
Loop detection
Harness logic that notices when an agent is repeating itself, such as calling the same tool with the same arguments again and again, and steps in or stops the run. See Ch 11 · Loop detection
Lost in the middle
The finding (Liu et al., 2024) that models use information near the start or end of a long context more reliably than information buried in the middle. See Ch 06 · Why more context isn't free

M

MAST
The Multi-Agent System Failure Taxonomy (Cemri et al., 2025), which sorts the ways multi-agent LLM systems fail into 14 failure modes under three categories: specification and system design, inter-agent misalignment, and verification and termination. See Ch 19 · The MAST taxonomy
MCP (Model Context Protocol)
An open protocol, open-sourced by Anthropic in November 2024, through which an application connects to servers that offer tools, readable resources and prompt templates in one standard way. See Ch 04 · MCP: tools as a shared protocol
MemGPT
A system (Packer et al., 2023) that treats the context window like an operating system's main memory, with the model calling functions to move information between it and external storage. See Ch 07 · Memory systems
Mesh
A decentralized topology in which agents talk directly to their peers, with no central coordinator deciding who acts next. See Ch 15 · Decentralized: mesh and handoff
Model proposes, harness disposes
The rule that anything the model outputs, such as a tool call or a plan, is only a proposal, and the harness's code checks it against schemas, permissions and budgets before deciding whether it happens. See Ch 08 · The model proposes, the harness disposes

N

Non-determinism
The fact that the same input can give different outputs from run to run (because of sampling, batching effects and model updates), so a single successful run proves very little. See Ch 01 · Non-determinism

O

Orchestrator-worker
A pattern in which a central orchestrator LLM breaks a task into subtasks at run time, hands them to worker LLMs or agents, and combines their results. See Ch 15 · Centralized: orchestrator-worker and hierarchy

P

Parallelization (sectioning, voting)
A workflow pattern that runs several LLM calls at once: in sectioning each call handles a different, independent part of the task, and in voting each call attempts the same task so the answers can be compared. See Ch 02 · Five workflow patterns
pass@k
The probability that at least one of k attempts at a task succeeds, which measures whether an agent can solve the task at all. See Ch 13 · pass@k vs pass^k
pass^k
The probability that all k attempts at a task succeed, which measures whether an agent solves it reliably every time, and falls fast as k grows. See Ch 13 · pass@k vs pass^k
Plan-and-execute
A pattern in which a planner first writes an explicit multi-step plan and an executor then carries out the steps, so code can check, budget or show the plan to a person before anything runs. See Ch 05 · Plan-and-execute
Procedural memory
Knowledge of how to do things, held in the model's weights and in the agent's own code, prompts and tool definitions. See Ch 07 · Memory systems
Prompt caching
A provider feature that reuses the processed form of a prompt prefix it has seen recently, so a call that starts with exactly the same prefix is faster and cheaper; any change early in the prompt invalidates the cache for everything after it. See Ch 06 · Ordering and the prompt-cache prefix
Prompt chaining
A workflow pattern that splits a task into fixed steps run in sequence, each LLM call working on the previous one's output, often with code checks (gates) in between. See Ch 02 · Five workflow patterns
Prompt injection
An attack in which text the model reads contains instructions that override what the developer or user intended; it remains unsolved because the model can't reliably tell instructions from data. See Ch 12 · Prompt injection: direct and indirect

R

ReAct
“Reason + Act” (Yao et al., 2022), a pattern in which the model alternates between a thought, an action such as a tool call, and an observation of the result, so facts from the world feed each next thought. See Ch 05 · ReAct
Reducer
A function that combines a node's update with the existing state (for example, appending to a list instead of overwriting it), so that updates from nodes running in parallel don't overwrite each other. See Ch 09 · State and reducers
Reflexion
A pattern (Shinn et al., 2023) in which, after a failed attempt, the agent writes a short reflection on what went wrong and keeps it in memory to guide its next attempt. See Ch 05 · Self-Refine and Reflexion
ReWOO
“Reasoning WithOut Observation” (Xu et al., 2023), a pattern in which a planner writes the whole tool chain up front with placeholders for results it hasn't seen, workers fill them in, and a solver writes the answer, avoiding a model call after every tool result. See Ch 05 · ReWOO and LLMCompiler
Routing
A workflow pattern in which a classifier (an LLM call or plain code) sorts an input into a category and sends it to a prompt, model or handler specialized for that category. See Ch 02 · Five workflow patterns

S

Sandbox
An isolated environment, such as a container with restricted file, network and system access, where agent-run code and tools execute so that mistakes or attacks can't reach the host. See Ch 12 · Sandboxing and egress control
Self-consistency
Sampling several independent chain-of-thought answers to the same question and taking the most common final answer (Wang et al., 2023). See Ch 05 · Chain-of-thought and self-consistency
Semantic memory
Memory of general facts, such as a user's preferences or how a codebase is laid out, kept apart from the particular episodes they were learned in. See Ch 07 · Memory systems
Semaphore
A concurrency primitive that lets at most N tasks into a section of code at once, used for example to cap how many model calls are in flight. See Ch 10 · Concurrency for agents
Span
One timed unit of work inside a trace, such as an agent's whole lifetime, one model call or one tool call, with a start, an end, attributes and a link to its parent span. See Ch 13 · Traces and the span model
Spawn
Creating a new child agent at run time with its own task, context and limits, which a harness handles as a lifecycle: propose, validate, create, register, schedule, run, return, aggregate. See Ch 16 · The spawn lifecycle
State machine
A model of a process as a fixed set of named states (such as running or done), with explicit rules for which event moves it from one state to another; any transition not listed is illegal. See Ch 09 · The agent lifecycle as a state machine
Stigmergy
Coordination through changes left in a shared environment rather than direct messages, as when ants follow pheromone trails laid by other ants; the term was coined by Pierre-Paul Grassé in 1959. See Ch 18 · Ant colonies and stigmergy
stop_reason
The field in a model response that says why generation stopped (for example end_turn, tool_use or max_tokens), and so the first branch an agent loop takes. See Ch 01 · stop_reason
Structured concurrency
A discipline in which concurrent tasks are started inside a scope that can't exit until all of them have finished or been cancelled, so no task outlives the code that started it. See Ch 10 · Concurrency for agents
Structured output
Model output constrained to a machine-readable format, such as JSON that matches a schema; even when the format is guaranteed, the content still has to be validated. See Ch 01 · Structured output is a proposal, not a fact
Subagent
An agent started by another agent to handle a subtask in its own fresh context and return a condensed result, usually exposed to the parent as just another tool. See Ch 16 · Subagent as a tool
Swarm
A loosely used name for many agents working with little or no central control, which in LLM work can mean handoff networks (as in OpenAI's experimental Swarm framework), simulated agent societies, or groups of agents that debate. See Ch 18 · What “swarm” means in LLM systems

T

TaskGroup
Python's asyncio.TaskGroup (added in 3.11), which runs a set of tasks inside an async with block, waits for all of them at the end, and cancels the rest if one fails. See Ch 10 · Concurrency for agents
Telephone game
The loss and distortion of information as tasks and findings are summarized and passed from agent to agent through a delegation tree, named after the children's game. See Ch 16 · Context passing and the telephone game
Timeout
A limit on how long an operation may take before it is abandoned, needed at every level, from a single model or tool call up to the whole run. See Ch 11 · Timeouts at every level
Token
The unit of text a model reads and writes, usually a piece of a word (roughly three-quarters of an English word on average, depending on the tokenizer); context limits and prices are counted in tokens. See Ch 01 · Tokens and the generation loop
Tool
A function the harness offers the model, described by a name, a plain-language description and a JSON Schema for its inputs; the model can ask for it to be called, and the harness runs it. See Ch 04 · Anatomy of a tool definition
tool_result
The content block the harness sends back in the next user message, carrying a tool's output (or its error) and matched to the request by its tool_use_id. See Ch 04 · The protocol
tool_use
The content block a model emits when it wants a tool run, holding a unique id, the tool's name and its input arguments; the response's stop_reason is then tool_use too. See Ch 04 · The protocol
tool_use_id
The id that pairs each tool_result with the tool_use block that asked for it; every request needs exactly one matching result, even when several calls run in parallel. See Ch 04 · The protocol
Trace
The record of one run, built from spans that share a trace id and nest through parent ids, so you can see which agent did what, when, and at what cost. See Ch 13 · Traces and the span model
Trajectory
The full sequence of observations and actions in one run, in practice the message history; sometimes also called a trace or rollout, and what trajectory evals grade. See Ch 03 · Anatomy: the minimum pieces
Tree of Thoughts (ToT)
A pattern (Yao et al., 2023) that treats reasoning as search: the model proposes several possible next steps, judges how promising each is, and the harness explores the best branches and backs out of dead ends. See Ch 05 · Search: Tree of Thoughts and LATS

V

Vector store
A database that stores embeddings and returns the entries closest to a query vector, so an agent can retrieve memories or documents by meaning rather than by exact words. See Ch 07 · Memory systems

W

Working memory
The information an agent holds for the decision it is making right now, which for an LLM agent is mostly what is in the context window at that step. See Ch 07 · Memory systems
